# AnimalGuide — справочник по животным, с которым разговаривают

Локальное веб-приложение: спрашиваете про животное обычными словами и
получаете карточку, собранную только из источников — русской Википедии и
GBIF. Латынь в карточке подтверждена GBIF, пересказ раздела — только того,
что агент действительно прочитал. Разделы карточки раскрываются по клику,
дерево классификации кликабельно («кто ещё входит в кошачьих?»), двух
животных можно сравнить таблицей, а несколько — собрать в подборку с
этапами «план → сбор → сверка → принята».

Под капотом — несколько агентов на DeepSeek (привратник названия,
идентификатор, специалисты по разделам, сравнение, ведущий разговора,
составитель подборки) и координатор, написанный кодом. Всё, что они
делают, видно в журнале хода: каждый запрос к модели, вызов инструмента,
цену и токены, а на вкладке «Промпты» — что именно ушло модели.

**Интересные факты (v18).** Рядом с приложением может круглосуточно работать
демон `animals-mcp -http`: раз в час он выбирает случайное млекопитающее из
эталонного списка [MDD](https://www.mammaldiversity.org) (6904 вида),
собирает о нём выпуск из 3–5 фактов по Википедии, GBIF и MDD, проверяет каждый
факт отдельным запросом к модели и сохраняет выпуск в SQLite. Раз в сутки —
сводка по выпускам. Выпуски, сводки и расписание доступны инструментами MCP
по HTTP, а в приложении — окном «Интересные факты» и механизмом `trivia`,
с которым ведущий сам берёт готовый выпуск о виде. Подробности — в разделе
[«Интересные факты: демон 24/7»](#интересные-факты-демон-247).

**Конвейер MCP-инструментов (v19).** У демона есть три самостоятельных
инструмента: `search` получает данные о виде (досье из MDD, Википедии и
GBIF), `summarize` обрабатывает их (3–5 проверенных фактов), `save_to_file`
сохраняет результат в файл Markdown или JSON. Цепочку по MCP ведёт клиент:
код (`cmd/pipeline`, вкладка «Конвейер») или модель, которая сама зовёт три
инструмента. Каждый шаг отдаёт конверт с отпечатком sha256 своих данных и
входа, поэтому порча данных по дороге и разрыв цепочки ловятся на обеих
сторонах. Подробности — в разделе
[«Конвейер: search → summarize → save_to_file»](#конвейер-search--summarize--save_to_file).

**Несколько MCP-серверов и длинный флоу (v20).** Приложение держит реестр
из трёх MCP-серверов: `sources` (stdio — Википедия и GBIF), `daemon` (HTTP —
справочник MDD и «Интересные факты») и `notes` (stdio — блокнот натуралиста,
новый). Модель получает инструменты всех трёх сразу и сама ведёт длинный
флоу «Паспорт вида в блокнот»: 13–18 вызовов на трёх серверах, от поиска
статьи до закрытого блокнота. Каждое имя инструмента закреплено за одним
сервером, поэтому вызов уходит туда, где инструмент живёт; дубли и платные
инструменты модели не выдаются. После модели код проверяет выбор, маршрут и
порядок вызовов — по зависимостям данных между ними и по счётчикам самих
серверов. Подробности — в разделе
[«Несколько MCP-серверов: реестр и длинный флоу»](#несколько-mcp-серверов-реестр-и-длинный-флоу).

**База знаний (v21).** У справочника появилась своя база знаний: замороженный
снимок 30 статей русской Википедии о хищных Евразии и документ «Хищные по MDD
v2.5», всего 31 документ, около 350 страниц. Документы режутся на фрагменты
двумя стратегиями — по фиксированному размеру и по структуре разделов, —
фрагменты кодируются эмбеддингами (локальная модель
`intfloat/multilingual-e5-base`) и сохраняются в SQLite с метаданными
(источник, статья, раздел, chunk_id). Поиск — по вектору, а без эмбеддера — по
BM25. Стратегии сравниваются на размеченных контрольных вопросах. Подробности —
в разделе [«База знаний: корпус, чанкинг, индекс»](#база-знаний-корпус-чанкинг-индекс).

**Ответ с базой знаний и без (v22).** Вопрос → поиск фрагментов в базе →
вопрос вместе с фрагментами → модель. В чате это механизм `rag`: код ищет по
базе до первого запроса ведущего, и тот отвечает по найденному, называя
источники `[chunk_id]`. В окне «База знаний» один и тот же вопрос задаётся
модели в двух режимах — без базы и с найденными фрагментами, — а 10
контрольных вопросов прогоняются в обоих режимах с оценкой правилом и
судьёй-моделью. Подробности — в разделе
[«Ответ с базой знаний и без»](#ответ-с-базой-знаний-и-без).

**Фильтр и переписывание запроса (v23).** Второй этап поиска по базе:
запрос переписывается (разговорные названия → канонические, вопрос-продолжение
получает вид из прошлой реплики), из 20 кандидатов фильтр релевантности
оставляет до 5 — выше откалиброванного порога косинуса, не хуже лучшего на Δ и
без повторов. Вопрос вне базы остаётся с пустой выдачей. Пять режимов ответа
сравниваются на контрольных вопросах, конфигурации поиска — матрицей.
Подробности — в разделе
[«Фильтр, переписывание запроса, режимы»](#фильтр-переписывание-запроса-режимы).

## Что нужно

- Go 1.25 или новее.
- Для поиска по эмбеддингам — [uv](https://docs.astral.sh/uv/): он сам
  поставит Python и sentence-transformers для локального эмбеддера
  (`embedder/`). Без него база знаний работает, но ищет только по BM25.
- Ключ DeepSeek: <https://platform.deepseek.com>.
- Браузер. Интернет нужен для запросов к модели и к источникам; CDN не
  используются — фронтенд встроен в бинарник.

## Быстрый старт

```bash
git clone https://github.com/AlexS8332/AnimalGuide_Task24.git
cd AnimalGuide_Task24
cp .env.example .env.local   # и вписать в .env.local свой DEEPSEEK_API_KEY
go build -o animalguide .    # на Windows: go build -o animalguide.exe .
./animalguide                # откроет http://127.0.0.1:8770 в браузере
```

Ключ можно не класть в файл, а задать переменной окружения
`DEEPSEEK_API_KEY` — окружение важнее файла. `.env.local` и `.env` ищутся в
рабочем каталоге и выше по дереву; в git они не попадают. Остальные
переменные (`DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `WIKIPEDIA_BASE_URL`,
`GBIF_BASE_URL`) необязательны — см. `.env.example`.

Для пробы без сборки хватит `go run .`.

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-addr` | `127.0.0.1:8770` | адрес, на котором слушать; приложение локальное, поэтому только петлевой интерфейс |
| `-open` | `true` | открыть браузер при старте; `-open=false` — не открывать |
| `-data` | `.` | каталог данных: `history`, `memory`, `profiles`, `collections`, `invariants` |
| `-features` | пусто | механизмы новых диалогов поверх умолчаний: `-guard`, `+facts,-extract`, `none,charter`, `all` |
| `-window` | `8` | сколько последних сообщений уходит модели дословно (механизм «Окно сообщений») |
| `-keep-tools` | `600` | до скольких символов сокращать ответы инструментов прошлых ходов (механизм «Сокращение») |
| `-context-limit` | `1048576` | свой лимит контекста в токенах, проверяется до отправки; `0` — не проверять |
| `-on-overflow` | `fail` | что делать при переполнении: `fail` — не отправлять, `trim` — выбрасывать старые ходы, `off` — отправить как есть |
| `-facts-server` | `TRIVIA_SERVER` или `http://127.0.0.1:8766` | адрес демона «Интересных фактов»; `-facts-server ""` — выключить раздел и механизм |
| `-mcp-config` | `MCP_CONFIG` или встроенная | конфигурация реестра MCP-серверов (образец — `mcp-servers.example.json`); встроенная — sources, daemon, notes |
| `-kb` | `KB_DB` или `<data>/kb.db` | база знаний, собранная `go run ./cmd/kb index` |
| `-embedder` | `EMBED_BASE_URL` или `http://127.0.0.1:8777` | адрес эмбеддера (OpenAI-совместимый `/v1/embeddings`: сайдкар `embedder/`, Ollama, облако) |

Пример: `./animalguide -addr 127.0.0.1:9000 -data ~/animalguide -features=-guard,-extract`.

## Механизмы и выключатели

Каждый механизм — строка реестра в `internal/features/catalog.go`: имя,
место блока в запросе, цена в токенах и запросах и запасной путь — что
происходит, если механизм выключен. Набор механизмов — свойство диалога,
а не сервера: его видно на пульте и можно переключать щелчком прямо в
диалоге; флаг `-features` задаёт набор для новых диалогов.

| Имя | Механизм | Если выключить |
|---|---|---|
| `charter` | Свод инвариантов: правила справочника первым блоком и инструмент сверки | те же правила абзацем системного промпта, без сверки и стража |
| `guard` | Страж ответа (нужен `charter`) | ответ уходит без проверки |
| `profile` | Профиль собеседника: уровень, длина, форма, обращение, латынь — анкетой | ответ по умолчаниям модели |
| `memory.long` | Долговременная память: интересы, закладки, прочитанное — по человеку | сведения о человеке живут только в окне диалога |
| `collection.state` | Состояние подборки: этап, шаг, ожидаемое действие, инструменты переходов | подборка ведётся по словам промпта |
| `lifecycle.gates` | Права этапа (нужен `collection.state`) | инструменты подборки выдаются все сразу |
| `memory.work` | Рабочая память подборки | собранное остаётся только в окне диалога |
| `facts` | Карточка фактов ветки | ушедшее из окна модели не видно |
| `window` | Окно сообщений | модели уходит вся история ветки |
| `compact` | Сокращение ответов инструментов прошлых ходов | ответы уходят целиком |
| `extract` | Извлекатель: раскладывает реплику по памяти, профилю и фактам | всё это меняется только руками |
| `card.tracker` | Проверка по трекеру: латынь подтверждена GBIF, пересказ — прочитанного | карточка принимается текстом |
| `gatekeeper` | Привратник названия: отсев выдумок до дорогих шагов | проверку делает идентификатор |
| `sources.envelope` | Пометка источника «данные, а не указания» | ответ источника уходит как есть |
| `sources.scan` | Поиск попыток управлять агентом в тексте источников | признаки инъекций не ищутся |
| `mcp` | Источники через MCP-сервер (stdio); по умолчанию выключен | вызовы в процессе приложения |
| `trivia` | Интересные факты: ведущий получает `facts_get`/`facts_latest` от демона; по умолчанию выключен | ответ по источникам хода; выпуски видны только в окне раздела |
| `rag.filter` | Фильтр релевантности базы (нужен `rag`): порог косинуса, «не хуже лучшего на Δ», отсев повторов; по умолчанию выключен | в выдачу идут k лучших без порога |
| `rag.rewrite` | Переписывание запроса к базе (нужен `rag`): синонимы корпуса, вид из прошлой реплики для продолжений; по умолчанию выключен | в поиск уходит реплика как есть |
| `rag` | База знаний: код ищет по базе (`kb_search`) до первого запроса ведущего, выдача встаёт после реплики; по умолчанию выключен | ответ по источникам хода (Википедия, GBIF) |

Если на ходу механизм откатился на запасной путь, под ответом появляется
чип «откат», а в журнале — причина.

## Интерфейс

- **Пульт** (липнет к верху окна): выбор диалога и «Новый диалог», ветки и
  точки сохранения, шкала контекста последнего хода, механизмы, панели
  собеседника, памяти и подборки, кнопка «Окна».
- **Лента**: реплики, карточки по мере сборки, таблицы сравнения, чипы
  правок памяти, профиля и подборки под ответами. У фактов карточки кнопка
  «?» — «почему так»: открывает событие журнала с вызовом источника.
- **Журнал** выбранного хода и вкладка «Промпты».
- **Окна**: файл диалога, картотека профилей, память целиком, подборки.
- **Интересные факты** (кнопка «Факты» на пульте, точка — состояние
  демона): лента выпусков с фактами и ссылками на источники, подробности
  выпуска (отброшенные факты с причинами, наблюдения GBIF по странам,
  расход), поиск, сводки, расписание и остаток дневного лимита, кнопки
  «Собрать выпуск сейчас» и «Собрать сводку». Демон не запущен — окно
  подскажет, как его запустить.
- Выгрузка карточки, сравнения и подборки в markdown.

Сервер ничего не знает об агентах: механизмы приносят свои разделы API
(`/api/people`, `/api/memory`, `/api/collections`) и свои панели в
интерфейс. Состояние хода живёт на сервере, идентификатор диалога — в
адресе страницы, поэтому перезагрузка страницы ничего не теряет.

## Где лежат данные

Всё — JSON-файлы в каталоге `-data` (по умолчанию рабочий каталог):

| Каталог | Что там |
|---|---|
| `history/` | диалоги: ветки, точки сохранения, ходы с журналами |
| `memory/long/` | долговременная память, файл на собеседника |
| `memory/work/` | рабочая память, файл на подборку |
| `profiles/` | анкеты собеседников |
| `collections/` | подборки: этап, план, собранные виды, отказы |
| `invariants/` | свод правил справочника |

У демона — одна база SQLite `trivia.db` в его каталоге `-data`: справочник
MDD, выборы видов и кэш проверок, выпуски, сводки, журнал запусков и выходы
шагов конвейера (7 дней). Схемы растут миграциями по компонентам (`mdd`,
`trivia`, `schedule`, `pipeline`). Файлы `save_to_file` — в `<data>/exports/`.

У каждого файла есть версия формата (`"schema": N`). Файл старого формата
читается через миграцию, а перед первой перезаписью рядом остаётся копия
`<имя>.v<N>.bak`. Файл новее кода не читается — приложение скажет об этом,
а не испортит его.

## Тесты

```bash
go test ./...
```

Тесты не ходят в сеть: модель, Википедия и GBIF подставные.

С детектором гонок:

```bash
go test -race ./...
```

`-race` требует cgo, то есть gcc. На Windows нужен gcc из mingw-w64
(например, из MSYS2: пакет `mingw-w64-x86_64-gcc`), и его каталог должен
стоять **первым** в `PATH`. gcc из `msys64\usr\bin` — cygwin-сборка, cgo её
не принимает («don't use the cygwin compiler…» или просто
«cgo.exe: exit status 2»). В PowerShell:

```powershell
$env:PATH = 'C:\msys64\mingw64\bin;' + $env:PATH
go test -race ./...
```

### Проверки интерфейса в браузере

Интерфейс проверяется в настоящем браузере — headless Microsoft Edge, без
Node и без драйверов:

```bash
go test -tags edge -run TestEdge -v .
```

Тест поднимает приложение на подставной модели с данными во временном
каталоге, заводит диалоги (карточка с разделами и деревом, сравнение в
своей ветке, подборка, пустой диалог) и открывает страницу в Edge с
подключённым сценарием `testdata/edge/scenario.js`. Сценарий нажимает те же
кнопки, что и человек, и пишет итог в страницу; тест снимает DOM
(`--dump-dom`) и превращает каждую строку в подтест — всего около шестидесяти пяти
проверок: пульт, ветки и точки, механизмы и выключатель, лента и карточка,
разделы и «прочитать», дерево и соседи, «почему так», журнал и «Промпты»,
окна, панель подборки с этапами, чипы, выгрузка markdown, новый диалог,
пустое состояние, живой ход, геометрия прокрутки и окно «Интересные факты» на подставном демоне (лента, подробности, поиск, сводки, «Собрать сейчас», экранирование, демон недоступен).

Edge ищется в стандартных местах установки; другой путь — переменная
`EDGE_PATH`. Если браузера нет, тест пропускается.

Снимки экрана тех же состояний:

```bash
EDGE_SHOTS=shots go test -tags edge -run TestEdge .
```

У headless Edge есть особенность: если прокручено само окно, снимок
`--screenshot` рисует страницу со сдвигом — над липким пультом пустое поле
высотой в прокрутку, хотя в DOM пульт стоит у верха. Поэтому для снимков
тест прокручивает `body`, а не окно, а положение пульта и журнала при
прокрутке проверяет по DOM.

## Опыт `-report`: испытания на живой модели

Регрессионный набор испытаний (И-1…И-8) гоняется одной командой вместо
запуска сервера. Каждое испытание сравнивает дорожки, отличающиеся ровно
одним механизмом, и проверяет пороги ТЗ; итог — markdown-отчёт.

```bash
go run . -report                      # все испытания → examples/report.md
go run . -report -trials 1,6          # только И-1 и И-6
go run . -report -report-out out.md   # отчёт в другой файл
```

- Запускать из корня репозитория: проверка совместимости читает
  `testdata/legacy/`.
- Диалоги, профили и подборки прогона остаются в `<-data>/bench/<время>/`,
  по каталогу на испытание: за любым числом отчёта можно пройти в файлы.
- Прогон всех испытаний — сотни запросов к модели; цена прогона есть в
  начале отчёта.
- И-7 (MCP) гоняет три дорожки: A — через MCP-сервер, B — в процессе, B′ —
  повтор B для замера шума модели. На дорожке A сервер убивается посреди
  вызова в шестом запросе: модель должна получить ошибку «MCP-сервер
  недоступен», а следующий ход — пойти через перезапущенный сервер.
  Холодный старт в отчёте включает сборку сервера, если бинарника нет;
  чтобы мерить сам запуск, соберите его заранее
  (`go build -o bin/ ./cmd/animals-mcp`) и передайте путь:
  `go run . -report -trials 7 -mcp-server bin/animals-mcp` (на Windows —
  `bin/animals-mcp.exe`).
- И-8 («Интересные факты по расписанию») собирает не приложение, а демон —
  с настоящими источниками и моделью, но на подставных часах: «час» проходит
  мгновенно. Проверяет выпуски по расписанию, догон после простоя, сводку,
  дневной лимит и инструменты по MCP. Справочник MDD скачивается (15 МБ);
  чтобы не качать его каждый прогон, укажите готовую базу:
  `TRIVIA_MDD_DB=путь/к/trivia.db go run . -report -trials 8`.

## MCP

Инструменты источников (Википедия и GBIF) можно вызывать не в процессе
приложения, а через MCP-сервер — отдельный процесс, который говорит по
протоколу [Model Context Protocol](https://modelcontextprotocol.io) через
stdio. Модель разницы не видит: описания инструментов сверяются с
локальными побайтно, результаты и тексты ошибок те же.

Включить для новых диалогов:

```bash
go run . -features +mcp
```

В открытом диалоге — выключатель «MCP-сервер источников» на пульте. Сервер
запускается при первом ходе с включённым механизмом; где взять бинарник,
приложение ищет так: флаг `-mcp-server путь` → `animals-mcp` рядом с
приложением → `PATH` → сборка из `./cmd/animals-mcp`. Готовые бинарники:

```bash
go build ./...                               # проверка сборки
go build -o . . ./cmd/animals-mcp            # приложение и сервер рядом
```

Что видно в интерфейсе: в журнале хода — `mcp.connect` и `mcp.tools`,
вызовы источников с пометкой «MCP»; окно «MCP-сервер» (кнопка «MCP: …» на
пульте) — статус, инструменты со схемами, счётчики вызовов приложения и
самого сервера. Если сервер не поднялся, ход идёт в процессе, а в журнале
написано почему.

Посмотреть сервер отдельно, без приложения:

```bash
go run ./cmd/mcp-list                        # рукопожатие, инструменты, проверочные вызовы
go run ./cmd/mcp-list -schemas -no-demo      # только список со схемами
go run ./cmd/mcp-list -i                     # ручной режим
```

## Интересные факты: демон 24/7

Демон — тот же бинарник `animals-mcp`, запущенный в долгоживущем режиме.
Он работает сам по себе: приложение, браузер и человек ему не нужны.

```bash
go build -o . ./cmd/animals-mcp
export DEEPSEEK_API_KEY=...        # демон берёт ключ только из окружения
./animals-mcp -http 127.0.0.1:8766 -data ~/animalguide-facts
```

Что он делает:

| Задание | Когда | Что |
|---|---|---|
| `issue` | раз в час (`-every`) | случайный вид из MDD → досье (MDD, Википедия ru/en, наблюдения GBIF за всё время и за 30 дней по странам) → редактор пишет 3–5 фактов со ссылками на источники → проверяющий отдельно сверяет каждый факт с цитируемыми материалами → выпуск в SQLite |
| `summary` | в 09:00 (`-summary-at`) | агрегат за сутки считает код (выпуски, виды, отряды, статусы МСОП, отбраковка, сбои, расход), модель пересказывает его; числа текста сверяются с агрегатом |
| `mdd` | в 04:00 (`-mdd-at`) | проверка нового релиза MDD по ETag; вышел — справочник перезагружается, событие попадает в сводку |

- **Выбор вида.** Статус МСОП выбирается с весом (редкие чаще), вид внутри
  статуса — равновероятно; вид годен, если есть статья в Википедии и не
  меньше 50 наблюдений в GBIF. Повторов нет 30 дней.
- **Лимит.** Не больше `-budget` долларов в сутки (по умолчанию $0.50);
  исчерпан — слот пишется в журнал как `budget`, модель не зовётся.
  Выпуск стоит около $0.002, сводка — около $0.001.
- **Простой.** Демон был выключен — после старта он догоняет ровно один
  пропущенный выпуск, а не все сразу. Первый старт с пустой базой сначала
  скачивает справочник MDD.
- **Разово, без 24/7:** `animals-mcp -run issue` (или `summary`, `mdd`) —
  одно задание и выход; удобно для cron или Планировщика заданий.
- **Без MCP:** `animals-mcp -daemon` — то же расписание без HTTP-сервера.

### MCP по HTTP

С `-http` демон — MCP-сервер (Streamable HTTP, путь `/mcp`, проверка живости
`/healthz`). Инструменты: источники и `mdd_*`, плюс `facts_latest`,
`facts_get` (по id, mdd-id, латинскому, английскому или русскому названию),
`facts_search`, `summary_get`, `schedule_status` и платные `summary_build`,
`run_now` (помечены как меняющие состояние).

Токен — переменная `MCP_TOKEN`: клиенты шлют `Authorization: Bearer …`.
Без токена демон слушает только петлевой адрес; на `0.0.0.0` или внешний
адрес без токена он не запустится.

```bash
go run ./cmd/mcp-list -url http://127.0.0.1:8766                  # список и проверочные вызовы (только чтение)
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call facts_latest -args limit=3
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call facts_get -args '{"species":"Лев"}'
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call run_now -args job=issue   # платно
```

### Приложение и демон

Приложение ищет демон по `-facts-server` (или `TRIVIA_SERVER`, по умолчанию
`http://127.0.0.1:8766`) с тем же `MCP_TOKEN`. В стартовом выводе — строка
«факты: … (подключён / не отвечает — …)». Окно «Интересные факты» работает
при подключённом демоне. Механизм `trivia` (`-features +trivia` или
выключатель на пульте) даёт ведущему `facts_get` и `facts_latest`: на
вопрос о виде, про который уже есть выпуск, он опирается на выпуск и
называет дату сбора. Демона нет — ход идёт как обычно, в журнале причина.

### Круглосуточно на Windows

Проще всего — отдельное окно консоли: `animals-mcp -http 127.0.0.1:8766`
работает, пока окно открыто; Ctrl+C останавливает его аккуратно (сначала
HTTP, потом планировщик). Чтобы демон поднимался сам после входа в систему, —
Планировщик заданий, а ключ — переменной пользователя:

```powershell
setx DEEPSEEK_API_KEY "..."          # один раз; значение увидят новые процессы
schtasks /Create /SC ONLOGON /TN AnimalGuideFacts /TR "C:\path\animals-mcp.exe -http 127.0.0.1:8766 -data C:\path\facts"
```

Процесс, убитый без сигнала (`taskkill /F`, `Stop-Process`), оставляет
незавершённый запуск в журнале; при следующем старте демон помечает его как
сбойный и продолжает по расписанию.

## Конвейер: search → summarize → save_to_file

Три инструмента демона (`animals-mcp -http`), каждый — обычный
MCP-инструмент: их можно позвать по одному (`mcp-list -call …`), а можно
цепочкой.

| Шаг | Инструмент | Вход | Выход | Цена |
|---|---|---|---|---|
| получить | `search` | `query` — mdd-id, латинское, английское или русское название (русское ищется в русской Википедии по «лат. …» во вступлении); или `random: true` | конверт `dossier`: вид MDD, материалы S1…Sn (MDD, статья ru/en, наблюдения GBIF по странам) | бесплатно |
| обработать | `summarize` | `input` — конверт досье целиком, или `ref` — его digest | конверт `facts`: заголовок, вступление, 3–5 фактов со ссылками, отброшенные с причинами | ≈ $0.002, под дневным лимитом `-budget` |
| сохранить | `save_to_file` | `input` / `ref` конверта фактов, `format` (`md` или `json`), `name` | конверт `file`: путь в `<data>/exports/`, размер, sha256 файла, цепочка отпечатков, начало текста | бесплатно |

**Как передаются данные.** Выход шага — конверт
`{kind, digest, input, data, summary, cost_usd}`: `digest` — sha256
канонического JSON данных (ключи по алфавиту, без пробелов), `input` —
digest того, из чего данные получены. Следующий шаг берёт конверт целиком
(`input`) или только ссылку (`ref`); выходы `search` и `summarize` демон
держит в SQLite 7 дней. Проверки:

- инструмент пересчитывает отпечаток пришедшего конверта — данные изменились
  по дороге → ошибка «отпечаток данных не совпал»; не тот вид данных
  (досье сразу в `save_to_file`) → ошибка с подсказкой, какой шаг пропущен;
- клиент пересчитывает отпечаток каждого ответа и сверяет «вход шага N+1 =
  выход шага N» — так видно, что сервер обработал именно то, что ему дали;
- `save_to_file` пишет файл атомарно, перечитывает и сверяет sha256; в
  подвал файла (в JSON — поле `chain`) записаны отпечатки досье и фактов.

Расход `summarize` пишется в журнал запусков демона (задание `pipeline`) и
входит в дневной лимит и в суточную сводку.

### Из консоли

```bash
./animals-mcp -http 127.0.0.1:8766 -data ~/animalguide-facts   # демон, как выше
go run ./cmd/pipeline манул                                   # цепочку ведёт код
go run ./cmd/pipeline -pass ref -format json "Ailurus fulgens" # передача по ссылке, файл JSON
go run ./cmd/pipeline -random                                  # случайный вид из MDD
go run ./cmd/pipeline -agent "полосатая гиена"                 # цепочку ведёт модель (нужен DEEPSEEK_API_KEY)
go run ./cmd/pipeline -json манул > trace.json                 # след цепочки целиком
```

Флаги: `-url` (по умолчанию `http://127.0.0.1:8766`), `-token` (или
`MCP_TOKEN`), `-format md|json`, `-pass inline|ref`, `-agent`, `-model`,
`-json`, `-timeout`. Код выхода 0 — только если цепочка сошлась.

Журнал печатает каждый шаг: вызов, короткий отпечаток выхода и входа
(`facts 241782f119ce ← 9e559b1f3bfe`), проверки ✓/✗, время, размер ответа,
цену. Примеры живых прогонов — в `examples/pipeline/` (журналы, след JSON,
сохранённые файлы).

**Исполнитель-модель** (`-agent`) получает только три инструмента и задачу
словами; данные передаёт по `ref`, а сами досье и факты не видит — только
вид, digest и короткий итог, так дешевле и пересказывать нечего. Ошибку
инструмента (выдуманный ref, пропущенный шаг) модель видит и может
исправиться. Когда она закончила, код проверяет её цепочку так же, как
свою: порядок, вид данных, «вход = выход», цепочку в файле, — и
отмечает проверкой «в итоговой цепочке».

### В приложении

Окно «Интересные факты» → вкладка «Конвейер»: вид (или «случайный вид»),
формат, передача (`inline` / `ref`), исполнитель (код / модель) и кнопка
«Запустить цепочку». Три карточки шагов обновляются по ходу: состояние,
итог, отпечатки, проверки; на стрелках — «вход = выход шага N ✓». Внизу —
путь к файлу, sha256, начало текста и последние прогоны. REST:
`POST /api/pipeline/runs`, `GET /api/pipeline/runs/{id}`,
`GET /api/pipeline/runs` (описание — `internal/feed/pipes.go`).

### Тесты конвейера

`go test ./internal/pipeline/... ./cmd/pipeline ./cmd/animals-mcp ./internal/daemon ./internal/feed`:
сквозная цепочка в процессе и по настоящему MCP по HTTP (inline и ref, md и
json); перехватчик транспорта портит байт в данных запроса к `summarize` —
цепочка падает на шаге 2, `save_to_file` не вызывается; сервер, который
«обработал не то», — разрыв цепочки; неверный вид данных, неизвестный ref,
обход пути в имени файла, исчерпанный лимит (модель не вызывается);
исполнитель-модель на сценариях: верная цепочка, пропущенный шаг с
исправлением, выдуманный ref, конец без сохранения.

## Несколько MCP-серверов: реестр и длинный флоу

Три MCP-сервера, у каждого своё дело:

| Сервер | Транспорт | Что умеет | Инструменты для модели |
|---|---|---|---|
| `sources` | stdio (`animals-mcp`) | русская Википедия и GBIF | `search_wikipedia`, `read_wikipedia`, `match_taxon`, `taxon_tree`, `taxon_children`, `vernacular_names` |
| `daemon` | HTTP (`animals-mcp -http`) | справочник MDD и «Интересные факты» | `mdd_get`, `mdd_search`, `mdd_changes`, `facts_latest`, `facts_get`, `facts_search`, `summary_get` |
| `notes` | stdio (`animals-mcp -role notes`) | блокнот натуралиста: разделы с источниками → файл | `nb_open`, `nb_add`, `nb_close` |

Блокнот — новый сервер: `nb_open{title, species}` отдаёт случайный
`notebook_id`, `nb_add{notebook_id, heading, text, cites}` добавляет раздел со
ссылками на инструменты-источники, `nb_close{notebook_id, format}` пишет
Markdown или JSON в `<data>/notes/`, перечитывает файл и сверяет sha256.

### Регистрация и маршрутизация

Серверы описаны в конфигурации — встроенной или своей
(`-mcp-config` / `MCP_CONFIG`, образец — `mcp-servers.example.json`):

```json
{"servers": [
  {"name": "sources", "transport": "stdio", "args": ["-mdd-sync=false", "-data", "${DATA}"],
   "expect": "animals-sources", "tools": ["search_wikipedia", "read_wikipedia", "..."]},
  {"name": "daemon", "transport": "http", "url": "${DAEMON}", "token_env": "MCP_TOKEN",
   "expect": "animals-daemon", "tools": ["mdd_*", "facts_get", "..."]},
  {"name": "notes", "transport": "stdio", "args": ["-role", "notes", "-data", "${DATA}"],
   "expect": "animals-notes", "tools": ["nb_*"]}
]}
```

- **Инструмент — ровно у одного сервера.** Список `tools` у сервера —
  явный (шаблон `*` в конце разрешён); одно имя в списках двух серверов —
  ошибка конфигурации, а не «кто первый». Поэтому модель видит обычные имена
  без префиксов, а маршрут однозначно следует из имени.
- **Лишнее скрыто.** Демон отдаёт и те же источники, что `sources`, и
  платные `run_now`, `summarize`…: в маршрутах они видны строками «дубль →
  sources» и «не разрешён», но модели не выдаются — запрет держится
  отсутствием инструмента. `server_info` — служебный, его читает реестр.
- **Сервер опознаётся по имени.** В `initialize` серверы называются
  `animals-sources`, `animals-daemon`, `animals-notes`; ответил не тот
  (старый бинарник, чужой процесс) — статус `mismatch`, инструменты не
  выдаются.
- **Недоступный сервер не роняет остальные**: у него статус `down` и
  подсказка, что сделать; флоу честно провалит шаги, которым он нужен.
- `${DATA}` — каталог данных приложения (`-data`), `${DAEMON}` — адрес
  демона (`-facts-server`). Бинарник stdio-серверов — `command` из
  конфигурации, иначе `-mcp-server`, иначе `animals-mcp` рядом с
  приложением, в `PATH` или сборка из исходников.

### Длинный флоу «Паспорт вида в блокнот»

Модель получает 16 инструментов трёх серверов, каталог серверов в системном
промпте и задачу словами: собрать паспорт вида (таксономия, описание,
интересные факты) из источников, записать в блокнот с ссылками на источники
и закрыть его. Жёсткого порядка ей не дают — выбор за ней. Типичный ход:

| № | Сервер | Инструмент | Откуда аргументы |
|---|---|---|---|
| 1 | sources | `search_wikipedia` | вид из задачи |
| 2 | sources | `read_wikipedia` | `title` ← ответ №1 |
| 3 | daemon | `mdd_search` | латинское или английское название |
| 4 | daemon | `mdd_get` | `id` ← ответ №3 |
| 5 | sources | `match_taxon` | `scientific_name` ← ответ №4 |
| 6–7 | sources | `taxon_tree`, `vernacular_names` | `usage_key` ← ответ №5 |
| 8 | daemon | `facts_get` | `species` ← ответ №4 (выпуска может не быть — это законный ответ) |
| 9 | notes | `nb_open` | вид из №4 |
| 10–12 | notes | `nb_add` × 3 | `notebook_id` ← ответ №9 |
| 13 | notes | `nb_close` | `notebook_id` ← ответ №9 |

Закончить модель может только завершающим `flow_done`, и код его не примет,
пока блокнот не закрыт.

### Как проверяются выбор, маршрут и порядок

Порядок вызовов у модели вправе меняться (независимые шаги она часто делает
одним ответом), поэтому проверяется не полная последовательность, а то, что
от неё действительно требуется:

- **выбор** — каждый обязательный шаг сделан нужным инструментом (сколько
  раз — в пределах), запрещённых вызовов нет, задействованы все три сервера;
- **маршрут** — каждый вызов обслужил сервер своего маршрута;
- **данные** — значение из ответа одного вызова пришло в аргументы более
  позднего (`mdd_search.species.*.id → mdd_get.id`, `nb_open.notebook_id →
  nb_add`…). Угадать `notebook_id` или `usage_key` модель не может, так что
  выполненная зависимость доказывает и порядок; в журнале это «← из №k»;
- **порядок** там, где данных нет: всё прочитано до первого раздела,
  разделы — до закрытия блокнота;
- **ссылки** — `cites` в разделах называют только инструменты, которые уже
  отвечали, и среди них есть и `sources`, и `daemon`;
- **свидетельство серверов** — `server_info` каждого сервера до и после
  флоу: сам сервер насчитал столько же вызовов каждого инструмента, сколько
  их в трассе (меньше — вызов не дошёл до того сервера, провал; больше —
  демон обслуживал и других клиентов, предупреждение).

Что это не формальность, показывают тесты: хорошую трассу портят по одному
(вызов переписан на другой сервер, удалён `mdd_get`, добавлен `run_now`,
`nb_add` после `nb_close`, ссылки без демона, сервер насчитал меньше), и
каждая порча даёт свою проваленную проверку.

## База знаний: корпус, чанкинг, индекс

### Корпус

`corpus/` — замороженный снимок, источник истины для индекса:

- 30 статей русской Википедии о хищных Евразии — от манула и харзы до
  волка и белого медведя — плюс обзорные «Кошачьи», «Псовые», «Куньи»;
- документ «Хищные (Carnivora) в Mammal Diversity Database», собранный
  **кодом** из справочника MDD v2.5: семейства, роды, виды, статусы МСОП
  (модель его не пишет, иначе база пересказывала бы саму модель). Это обзор
  хищных по релизу v2.5, а не список его изменений: в v2.5 систематика
  отряда относительно v2.4 не менялась (так и написано в документе).
  Поэтому вопросы «конфликт с памятью модели» опираются на числа MDD v2.5,
  которые модель по памяти обычно называет иначе (2 вида малых панд
  *Ailurus*, 46 видов кошачьих и т. п.), а не на новые изменения релиза —
  это отклонение от предложения, где конфликт задумывался через изменения
  систематики;
- всего 31 документ, около 631 тыс. символов (350 страниц по 1800 знаков).

У каждой статьи записаны ревизия (`revid`) и постоянная ссылка на неё:
TextExtracts всегда отдаёт текущую версию, поэтому без снимка повторный прогон
шёл бы по другим текстам. `MANIFEST.json` хранит sha256 каждого файла и
`corpus_sha` всего корпуса; загрузка сверяет их, и правка руками — ошибка, а не
тихо другой корпус. Тексты Википедии — CC BY-SA 4.0, MDD — CC BY 4.0, атрибуция в
`corpus/LICENSE.md`; лицензия текстов корпуса отличается от лицензии кода.

Разделы хранятся с **собственными** телами (без текстов подразделов) и путём
«Образ жизни › Питание»; служебные разделы (Примечания, Литература, Ссылки…)
отброшены. Обновить снимок — осознанное действие:
`go run ./cmd/kb fetch -mdd-db путь/к/trivia.db` (без `-mdd-db` документ MDD
остаётся прежним).

### Две стратегии чанкинга

| Стратегия | Как режет | Параметры |
|---|---|---|
| `structure` | граница — заголовок: собственное тело раздела — фрагмент; длиннее Max — по абзацам, затем по предложениям (и поровну, а не жадно); короче Min — склеивается с соседом того же родителя | Max 1200, Min 200 символов |
| `fixed` | окно фиксированного размера по сплошному тексту документа с перекрытием, без оглядки на разделы; граница сдвигается к пробелу; раздел фрагмента — тот, где лежит большая часть его текста | размер — медиана структурных фрагментов (846), перекрытие 15 % (`-overlap 0` — без перекрытия) |

Max — предел резки, а не жёсткий потолок: короткий хвост (< Min) склеивается
с соседом, если вместе выходит не больше Max + Min, поэтому отдельные
фрагменты `structure` бывают до 1400 символов.

Размер `fixed` равен медиане `structure`, чтобы сравнивались границы, а не
размер. У каждого фрагмента метаданные: `chunk_id` (`manul/structure/004`),
`doc_id`, `source`, `title`, `section`, `section_path`, `strategy`, смещения в
тексте документа, токены, sha текста, ссылка и ревизия. Эмбеддеру уходит текст с
заголовком «Статья › Раздел» — так «питание манула» находится, даже когда в
абзаце нет слова «манул».

### Эмбеддинги и индекс

У DeepSeek эмбеддингов нет. Основной путь — локальный сайдкар `embedder/`
(Python через uv, `intfloat/multilingual-e5-base`, 768 измерений, CPU), с
OpenAI-совместимым API; тот же клиент без изменений ходит в Ollama или облако
(`EMBED_BASE_URL`, `EMBED_MODEL`, `EMBED_API_KEY`). Подробности —
`embedder/README.md`.

Индекс — отдельный файл SQLite `kb.db` (не в git: он пересобирается из
корпуса): документы, индексы, фрагменты с векторами, кэш векторов по
(модель, sha текста) и полнотекстовый индекс FTS5 — своя таблица на каждый
индекс, поэтому статистика BM25 (IDF, средняя длина) считается по фрагментам
этого индекса и ранги не зависят от того, какие ещё индексы собраны в
базе. Поиск — перебор косинуса в
памяти (сотни фрагментов — миллисекунды). Если эмбеддер не отвечает, индекс
построен другой моделью или собран без векторов, поиск откатывается на BM25 и
называет причину.

```bash
uv run embedder/server.py                         # эмбеддер (первый раз — загрузка модели ~1 ГБ)
go run ./cmd/kb index -strategy all               # оба индекса в kb.db (минуты на CPU; повтор — из кэша)
go run ./cmd/kb search "чем питается манул"       # топ обоих индексов
go run ./cmd/kb search -mode bm25 "кошачий медведь"
go run ./cmd/kb stats                             # документы, страницы, corpus_sha, индексы
go run ./cmd/kb eval -bm25                        # сравнение стратегий → examples/kb/chunking.md и .json
```

Без uv: `go run ./cmd/kb index -strategy all -embedder none` — индексы для BM25.

`kb eval` **перезаписывает закоммиченный отчёт** `examples/kb/chunking.md`
(и `chunking.json` рядом). Если векторный поиск не состоялся (эмбеддер не
отвечает, индекс без векторов), в этот путь он не пишет и просит указать
`-out` явно: отчёт по BM25 не должен выдавать себя за сравнение с
векторами.

Флаги эмбеддера у `cmd/kb`: `-embedder` — **вид** (`auto` — HTTP, если
отвечает, иначе без векторов; `http`; `hash` — тестовый; `none`), `-embed-url`
— **адрес** (иначе `EMBED_BASE_URL`, иначе `http://127.0.0.1:8777`). У
приложения флаг `-embedder` — это адрес: видов там нет. База — `-db`, по
умолчанию `KB_DB` (как у приложения), иначе `kb.db`.

### Контрольные вопросы и сравнение

`eval/questions.json` — 36 размеченных вопросов: 10 контрольных (`test`),
18 для подбора параметров (`dev`) и 8 вне базы (`out`); в сравнении стратегий
участвуют 26 вопросов с доказательствами (без «вне базы» и «аспекта нет»).
Релевантность задаёт
**дословный фрагмент-доказательство** из документа, а не `chunk_id`: фрагмент
считается найденным, если его на 80 % покрывает фрагмент индекса. Так разметка
не зависит от стратегии чанкинга, а тест проверяет, что каждое доказательство
действительно есть в своём документе. Разметка закоммичена раньше кода
чанкера.

На 26 вопросах разница в один-два вопроса — шум, поэтому вывод отчёта
говорит в вопросах («21 из 26 против 19 из 26, +2»), сравнивает стратегии
попарно по каждому вопросу (у скольких ранг лучше, хуже, равен) и называет
одну «лучше» только при перевесе не меньше 3 вопросов в парном сравнении по
recall@5; иначе — «разница в пределах шума». Для многофактных вопросов
(сравнение, multihop) считается ещё `recall_all@5` — все доказательства в
топ-5, — и то же в бюджете токенов. «Разорвано доказательств» (покрыто
< 80 %) при коротких цитатах почти всегда 0 у обеих стратегий; строже —
доля доказательств, целиком лежащих в одном фрагменте.

Вопрос-продолжение (`followup`) ищется как предыдущие реплики + вопрос
(`Context` + `Q`) — это «идеальный rewrite»: в живом диалоге запрос ещё
придётся переписать, и recall там будет не выше.

Итог сравнения (`examples/kb/chunking.md`, e5-base, dev+test, 26 вопросов):

| | structure | fixed |
|---|---:|---:|
| фрагментов | 777 | 884 |
| на стыке разделов | 3,5 % | 42,9 % |
| оборвано посреди предложения | 0 % | 98,8 % |
| доказательство целиком в одном фрагменте | 30 из 30 | 29 из 30 |
| recall@5, вопросов | 21 из 26 | 19 из 26 |
| recall@1 / @3 | 0,50 / 0,73 | 0,42 / 0,69 |
| MRR | 0,64 | 0,56 |
| все доказательства в топ-5 (`recall_all@5`) | 20 из 26 | 18 из 26 |
| первый релевантный в бюджете 1500 токенов | 22 из 26 | 19 из 26 |
| BM25: recall@5, вопросов | 21 из 26 | 20 из 26 |

По поиску разница **в пределах шума**: в топ-5 только у structure — 2
вопроса, только у fixed — 0 (порог — 3); по рангу первого релевантного
structure лучше в 9 вопросах, fixed — в 6, равны в 11. Устойчиво различается
структура: у structure фрагмент — законченный раздел, у fixed 43 % окон на
стыке разделов и почти все оборваны посреди предложения. BM25 справочно идёт
вровень с векторным поиском (21 против 21 у structure; в топ-5 только у
каждого — по 3 вопроса) и находит то, что тот пропускает (разговорное
«кошачий медведь»), — это задел для переписывания запроса.

## Ответ с базой знаний и без

### Как устроено

Ответ по базе — три шага: **вопрос → поиск фрагментов** (`kb_search`,
индекс `structure`, k = 5) **→ вопрос вместе с фрагментами → модель**. Где
это работает:

- **Отвечающий агент** (`internal/rag`, `Answerer`) — один запрос к модели
  без инструментов, температура 0. Два режима отличаются **только**
  контекстом: `norag` — системный промпт и вопрос; `rag` — тот же промпт плюс
  правило «опирайся только на фрагменты, называй `[chunk_id]`, нет ответа во
  фрагментах — скажи, что в базе этого нет» и фрагменты после вопроса. На нём
  стоит сравнение режимов: у ведущего справочника есть Википедия и GBIF, и
  «без базы» с ними было бы «модель с живыми источниками», а не «модель без
  базы».
- **Механизм `rag` в чате** — ведущий получает `kb_search`, а код вызывает
  его **до первого запроса** с репликой человека (`agent.Preload`). Выдача
  встаёт после реплики, а не блоком перед историей: блоки идут системными
  сообщениями перед окном, и блок, меняющийся каждый ход, обнулял бы кэш
  префикса всего окна. В журнале хода — «заказан вызов kb_search кодом» и сам
  вызов. Базы нет — механизм откатывается с причиной. Голое название
  («манул») и «сравни» идут мимо ведущего (карточка, сравнение) — там база
  пока не участвует.

Включить в чате — выключатель «База знаний (RAG)» на пульте или
`-features +rag` для новых диалогов. Нужна собранная база (`kb.db`) и, для
векторного поиска, эмбеддер (`uv run embedder/server.py`).

### Оценка ответа: правило и судья

Каждый ответ оценивают два голоса:

- **правило кодом** — по `expect` вопроса: группы обязательных слов (по
  основам), числа с допуском (с учётом «1,5»/«1.5», диапазонов «2–3», «тыс.»,
  чисел словами), недопустимые ответы; явный отказ («не знаю», «в базе этого
  нет») — `abstain`;
- **судья-модель** — видит вопрос, эталон, доказательства и **один** ответ,
  не зная режима: ссылки `[chunk_id]` и слова «в базе знаний»,
  «во фрагментах» перед судьёй вырезаются, ответы обоих режимов идут в
  перемешанном порядке.

Итог прогона — вердикт судьи; согласие голосов — отдельная метрика,
расхождения — списком в отчёте. Для вопросов без ответа в базе правильный исход
— «не знаю»; ответ по существу там — ошибка.

### Контрольные вопросы и проба

10 контрольных вопросов (`eval/questions.json`, набор `test`) — факт, число,
конфликт с памятью модели (MDD v2.5), вопрос к разделу, сравнение двух статей,
составной, разговорное название, продолжение с местоимением, «аспекта нет» и
«вида нет». У каждого — ожидание (`expect`) и источники (`sources`,
`evidence`).

**Проба дискриминативности** (`kb probe`, `examples/rag/probe.md`): каждый
отвечаемый вопрос трижды задаётся модели без базы; если она отвечает верно в 2
из 3 — вопрос не годится для сравнения. Из 26 вопросов модель знала 4, в том
числе контрольный T05 — он перенесён в dev (D19), его место занял T11.

### Итог сравнения (`examples/rag/compare.md`)

`deepseek-v4-flash`, 10 вопросов test, по 2 повтора, судья — та же модель:

С базой модель отвечает верно там, где поиск нашёл нужный фрагмент (монета

## Фильтр, переписывание запроса, режимы

### Второй этап поиска

```
вопрос ──переписывание──▶ запрос(ы) ──▶ 20 кандидатов (dense и BM25)
       ──реранкинг──▶ порядок ──фильтр──▶ до 5 фрагментов (или ни одного)
```

- **Переписывание кодом** (`rag.rewrite`, 0 запросов к модели):
  - разговорные названия и синонимы из корпуса раскрываются в канон: «кошачий
    медведь» → малая панда. Словарь собирается из названий статей, синонимов
    и оборотов «X или Y» первого предложения; варианты «кот ↔ кошка»;
  - определения перед названием не раскрываются — «эфиопский волк»,
    «американский красный волк», «барсук-медоед», «наложить перевязку»;
  - вопрос-продолжение без названия вида («а сколько она весит?») получает
    прошлую реплику, где вид назван;
  - латынь идёт только в BM25-запрос;
  - переписанный запрос уходит **только в поиск**, модель отвечает на исходный
    вопрос.
- **Переписывание моделью** (`-rewrite llm`, +1 запрос) — для сравнения в
  консоли и окне.
- **Реранкинг:**
  - `hybrid` — RRF рангов dense и BM25, бесплатно;
  - `llm` — оценка кандидатов моделью, платно, только для сравнения.
- **Фильтр** (`rag.filter`):
  - абсолютный пол косинуса — откалиброванный порог, хранится в индексе;
  - относительный порог «не хуже лучшего на Δ = 0,05»;
  - отсев повторов текста.

  Если вид прямо назван в реплике («якорь»), абсолютный пол не применяется: у
  фрагментов статьи о названном виде косинус всегда высокий, и пол ничего не
  различает. Фильтр отсекает всё — выдача пуста: в базе ответа, вероятно, нет.

### Калибровка порога (`examples/rag/calibrate.md`)

Порог подбирается только на dev и вопросах вне базы, а на test только
проверяется. Правило — середина зазора между лучшим косинусом вопросов вне
базы (максимум 0,822) и косинусом доказательства у dev-вопросов без названного
вида (минимум 0,837). Выбрано **0,829**, запас ≈0,007 в обе стороны.

`go run ./cmd/kb calibrate -write` записывает порог в индекс; без записи
действует умолчание 0,80.

### Матрица режимов поиска (`examples/rag/filter.md`)

K1 = 5, «доказательство в итоговой выдаче», 27 отвечаемых вопросов dev+test и
10 неотвечаемых:

| конфигурация | найдено из 27 | пусто на неотвечаемых | токенов выдачи |
|---|---:|---:|---:|
| `base` — dense top-5 | 19 | 0 из 10 | 1429 |
| `filter` | 18 (−T06) | 7 из 10 | 874 |
| `rewrite` | 26 | 0 из 10 | 1372 |
| `both` — rewrite + filter | 25 (−T06) | 7 из 10 | 906 |
| `hybrid` — rewrite + RRF + filter | 25 | 7 из 10 | 869 |

- Переписывание находит синонимы (T07 «кошачий медведь», D-синонимы) и
  продолжения (T08, D15, D16).
- Фильтр вдвое сокращает контекст и опустошает выдачу на **всех** вопросах вне
  базы (7 из 7). На вопросах «вид есть, аспекта нет» он выдачу не опустошает:
  вид назван, якорь.
- Цена фильтра — T06 («гепард для бедных», вид не назван). Его лучший
  косинус 0,818 ниже максимума вне базы 0,822: шкалы e5 перекрываются, и
  никакой абсолютный порог их не разделит.
- Гибрид в `both` не входит: на dev он дал только −D16 (ранг 5 → 12) и MRR
  0,63 → 0,53.
