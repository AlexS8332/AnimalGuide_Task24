# Изменения

Версия продукта равна номеру последнего сданного упражнения. По записи на
упражнение: что добавилось, что сломалось бы без миграции, во что обошлось по
цене хода.

## v23 — фильтр, переписывание запроса, сравнение режимов (2026-10-02)

- калибровка порога на dev+out — 0,829, середина зазора 0,822…0,837;
- матрица поиска (`examples/rag/filter.md`): переписывание — 26 из 27
  доказательств в топ-5 против 19 у base; фильтр пустеет на всех вопросах вне
  базы (7 из 7) и вдвое сокращает контекст; потеря — T06;
- ответы пяти режимов (`examples/rag/modes.md`): rag 5, rag+filter 3,
  rag+rewrite 6, rag+both 6 из 10, уверенных ошибок с базой 0.

И-11 — одна проверка честно не проходит: recall на test с фильтром −0,125
(T06, перекрытие шкал косинуса). Контрольный прогон в Edge — поиск «до и
после», «Спросить», «Режимы», «Контрольные вопросы».

Новое:

  - переписывание кодом: словарь синонимов корпуса, «X или Y», «кот ↔ кошка»,

## v19 — конвейер MCP-инструментов (2026-09-25)

Приёмка — живые прогоны против демона на `deepseek-v4-flash`: цепочка
search → summarize → save_to_file сошлась во всех режимах — исполнитель-код
(inline и ref, md и json, по русскому, латинскому, английскому названию,
mdd-id и случайному виду) и исполнитель-модель (сама вызвала три
инструмента по порядку, передавая данные по ref). Цепочка — 4–9 с,
$0.0005–0.003 (дешевле всего при кэше префикса у повторного вида).
sha256 файла на диске, пересчитанный отдельно, совпал с заявленным
инструментом; отпечатки в файле — с отпечатками шагов. Контрольный прогон в
Edge — 10 проверок из 10. Остальное — без изменений против v18.

Новое:

- **Три MCP-инструмента демона** (`internal/pipeline`): `search` (получить
  досье о виде без модели; русское название — через «лат. …» во вступлении
  статьи русской Википедии), `summarize` (обработать: редактор и
  проверяющий v18 над готовым досье — `trivia.Builder.Compose`; платно, под
  дневным лимитом, расход в журнале запусков как задание `pipeline`),
  `save_to_file` (сохранить Markdown или JSON в `<data>/exports/`: безопасное
  имя, атомарная запись, перечитывание и сверка sha256).
- **Конверт между шагами**: kind, data, digest (sha256 канонического JSON),
  input (digest входа). Вход — конверт (`input`) или ссылка (`ref`); выходы
  шагов хранятся в SQLite (компонент миграций `pipeline`, 7 дней). Порча
  данных, не тот вид данных, неизвестный ref — понятные ошибки инструмента.
- **Исполнители цепочки по MCP**: `pipeline.Run` — код, с проверками на
  каждом шаге (отпечаток ответа, вид, «вход = выход предыдущего», цепочка в

  проверяет её цепочку.
- **CLI `cmd/pipeline`** — журнал цепочки по шагам, `-json` — след целиком.
- **Приложение**: вкладка «Конвейер» в окне «Интересные факты» (три шага со
  стрелками, проверки, итог и файл, последние прогоны), REST
  `/api/pipeline/runs`; 13 новых Edge-проверок.
- `summarize` и `save_to_file` не повторяются клиентом после обрыва
  транспорта — как платные `run_now` и `summary_build`.

Найдено вживую: CLI печатал шаги исполнителя-модели дважды (итоговая
проверка цепочки приходит повторным onStep); расход модели-исполнителя
считался по имени модели из ответа API, которого нет в таблице тарифов, —
обнулялся.

## v18 — интересные факты по расписанию (2026-09-25)

Приёмка: `-report` на `deepseek-v4-flash` — И-1…И-8 приняты, 65 проверок
из 65, прогон $0.54 за 15 минут (`examples/report.md`; прогон шёл в пиковые
часы DeepSeek — тариф вдвое выше, чем у приёмки v17). И-8: 11 из 11 —
выпуски по расписанию, ровно один догон после простоя 5 ч, агрегат сводки
сходится с базой и числа текста прошли сверку, слот при исчерпанном лимите —
`budget` без выпуска и расхода, по MCP те же выпуски, что в базе. Выпуск
$0.0023 и 4,9 с, сводка $0.0012, отброшено 5 % фактов. И-1…И-7 — без
регрессии.

Новое — демон «Интересных фактов»: `animals-mcp -http` (или `-daemon`)
работает сам по себе, раз в час собирает выпуск о случайном млекопитающем,
раз в сутки — сводку, и отдаёт всё по MCP (Streamable HTTP). Приложение
получило окно «Интересные факты» и механизм `trivia`.

- **Справочный слой MDD** (`internal/mdd`). Mammal Diversity Database — 6904
  вида, архив с GitHub (проверка обновления по ETag), разбор CSV, SQLite.
  Инструменты `mdd_get`, `mdd_search`, `mdd_changes` — и в stdio-сервере.
  «Domesticated» не считается страной, «NT (as …)» сводится к коду.
- **Общая база** (`internal/db`): SQLite на `modernc.org/sqlite` (без cgo),
  WAL, миграции по компонентам (`mdd`, `trivia`, `schedule`) в одной
  `trivia.db`. Время — INTEGER наносекунды: границы «ровно равно» точны.
- **Выбор вида** (`trivia.Picker`, `WebChecker`). Статус МСОП — с весом ×
  число видов, вид внутри — равновероятно; годен, если есть статья
  (англовики по латыни → langlink ru) и ≥ 50 наблюдений GBIF. Повторов нет
  30 дней, проверки кэшируются на 30 дней. Порядок проверок «GBIF → статья»
  выбран замером: на 152 видах GBIF отсекает 35 %, статья — 0,7 %.
- **Выпуск** (`WebCollector`, `LLMEditor`, `LLMVerifier`, `Builder`). Досье
  собирает код: MDD, статья ru или en (вступление + до 4 тематических
  разделов), наблюдения GBIF по странам за всё время и за 30 дней со
  сверкой с ареалом MDD (ISO-2 → 241 имя стран MDD). Редактор пишет 3–5
  фактов по-русски со ссылками S1…Sn; код отбраковывает факты без источника
  или со ссылкой в никуда; проверяющий — отдельный запрос, видит только
  цитируемые материалы — отбрасывает неподтверждённое (с причиной), тем же
  запросом проверяет заголовок и вступление. Статусы ok / thin / failed.
  Конвейер карточки v17 для выпуска не используется: он читает только
  ru-Википедию, а у заметной доли видов статья лишь на английском.
- **Планировщик** (`internal/schedule`): задания по интервалу и по времени
  суток, журнал `schedule_run`, один запуск задания за раз, догон после
  простоя — ровно один, дневной лимит на модель (слот `budget` пишется в
  журнал), расход учитывается и у упавшего запуска, подставные часы в тестах.
  Задание видит свой запуск в контексте (`schedule.CurrentRun`).
- **Сводка** (`Aggregator`, `LLMSummarizer`). Агрегат за период считает код;
  модель пересказывает, код сверяет каждое число текста с агрегатом (одна
  повторная попытка, потом ошибка — сводка всё равно сохраняется).
- **Демон** (`internal/daemon`, `cmd/animals-mcp`): `-daemon`, `-http`,
  `-run issue|summary|mdd`, `-every`, `-summary-at`, `-mdd-at`, `-budget`.
  Первый старт с пустой базой сначала грузит MDD. Свежий HTTP-клиент на
  каждый выпуск (кэш источников вечный). Инструменты MCP: `facts_latest`,
  `facts_get` (в т.ч. по русскому названию), `facts_search`, `summary_get`,
  `schedule_status`, платные `summary_build` и `run_now` (без пометки
  «только чтение»). Сводка по запросу пишется в журнал — её расход виден
  лимиту.
- **MCP по HTTP** (`internal/mcp`): Streamable HTTP без сессий, `/mcp` и
  `/healthz`, токен `MCP_TOKEN` (Bearer, сравнение за постоянное время),
  отказ слушать не-loopback без токена, защита от кросс-сайтовых запросов;

## v17 — источники через MCP (2026-09-23)

Приёмка: `-report` на `deepseek-v4-flash` — И-1…И-7 приняты, 54 проверки
из 54, прогон $0.29 за 15 минут (`examples/report.md`). И-7: описания
инструментов на путях через MCP и в процессе совпадают побайтно, постоянная
часть A − B = 0, все вызовы источников дорожки A — через MCP, убитый посреди
вызова сервер поднимается следующим вызовом. Время хода A/B = 1,15 (шум
B′/B = 1,08), накладные на вызов источника p50 ≈ +110 мс — в основном второй
кэш источников в процессе сервера.

Механизм `mcp`: те же шесть инструментов Википедии и GBIF, но путь до них —
через MCP-сервер `v16`, отдельный процесс. Нового результата нет, блока в
запросе нет — это новый путь до существующего источника.

- `internal/mcp` — клиент как `tools.Source`: `initialize` → `tools/list` →
  сверка отпечатка описаний с локальными (расхождение — `ErrDrift`, бинарник
  устарел). Пропускаются только шесть инструментов источников, лишние — в
  журнал. Ответы помечены как недоверенные (`Untrusted`), вызов в журнале —
  «через MCP». Сбой транспорта модель получает словами: «MCP-сервер
  недоступен: …».
- Процесс сервера запускается лениво — первым ходом с `mcp`; с выключенным
  механизмом процесса нет вовсе. Поиск бинарника: флаг `-mcp-server` → рядом
  с приложением → `PATH` → сборка `./cmd/animals-mcp` из исходников (предел
  60 с). stderr сервера — в журнал приложения с префиксом `mcp:`. Упавший
  сервер поднимается следующим вызовом; больше трёх перезапусков в минуту —
  отложен на 5 минут.
- Путь выбирается на старте хода и внутри хода не меняется. Сервер не
  поднялся — ход идёт в процессе, в журнале причина, в `Effective` хода
  `mcp=false`.
- Журнал: `mcp.connect` (сервер, версия, протокол, pid) и `mcp.tools`
  (инструменты со схемами) на каждом ходе с MCP. Окно «MCP-сервер» и значок
  статуса на пульте (`ready/dead/drift/unavailable`), API `GET /api/mcp`.
- Запись в `features`: транспорт, по умолчанию выключен.
- Испытание И-7 в `-report`: дорожки A (через MCP), B (в процессе) и B′
  (повтор B, шум модели) на запросах И-1, разделах, узле дерева и
  сравнении; на A сервер убивается посреди вызова. Проверки: описания
  инструментов в запросах A и B совпадают побайтно, постоянная часть A − B
  = 0, вызовы источников A — 100 % через MCP и сходятся со счётчиком
  сервера, B — 0 %, пороги И-1 на обеих дорожках, брака нет, после
  убийства модель получает «MCP-сервер недоступен», следующий ход идёт
  через перезапущенный сервер. Отчётные числа — время A/B, кэш, холодный
  старт, накладные на вызов, HTTP-запросы к источникам (`server_info`
  отдаёт `http_requests`), тексты ошибок, совпадение вызовов A/B и B/B′.

- id вызова кодом (`pre_…`) теперь выводится из агента, инструмента и
  аргументов, а не из общего счётчика: тот же вызов даёт те же байты
  запроса на обоих путях и в любом прогоне — кэш префикса не сбивается.

Совместимость: у старых диалогов ключа `mcp` в наборе механизмов нет — он
выключен, миграция не нужна. Формат файлов не менялся.

Цена хода: 0 токенов, 0 запросов к модели, кэш префикса не трогает —
описания инструментов те же побайтно. Цена вне модели: второй процесс,
задержка JSON-RPC на каждый вызов источника, второй кэш источников в
процессе сервера.

НТ-1 («один файл») теперь выполняется как `go build ./...`: приложение
плюс бинарник сервера рядом с ним. Без бинарника приложение соберёт сервер
само при первом ходе с `mcp`, если рядом исходники и Go.
