# embedder — локальный сервер эмбеддингов

У DeepSeek нет API эмбеддингов, а базе знаний нужны векторы фрагментов и
вопросов. Этот сайдкар — один Python-файл на `sentence-transformers` с
OpenAI-совместимым API (`POST /v1/embeddings`, `GET /v1/models`) и
`GET /health`. Приложение ходит в него обычным HTTP-клиентом; без
сайдкара поиск по базе работает лексически (BM25), так что Python для
запуска приложения не обязателен.

## Запуск

Нужен [uv](https://docs.astral.sh/uv/). Зависимости (Python 3.11–3.12,
torch, sentence-transformers) uv поставит сам по метаданным в начале
`server.py`:

```sh
uv run embedder/server.py
# параметры по умолчанию:
#   --host 127.0.0.1 --port 8777
#   --model intfloat/multilingual-e5-base --device cpu   (cpu | cuda | auto)
```

Когда в выводе появится строка
`готов: модель intfloat/multilingual-e5-base, размерность 768, устройство cpu`,
сервер принимает запросы. Проверка: `curl http://127.0.0.1:8777/health`.

- **Первый запуск** скачивает модель (~1,1 ГБ) в кэш Hugging Face
  (`~/.cache/huggingface`) и ставит torch — несколько минут. Дальше старт
  занимает около минуты на CPU (загрузка весов).
- **CPU по умолчанию.** На Windows torch из PyPI ставится в CPU-сборке, и
  для базы в сотни фрагментов этого хватает: ~7 фрагментов по 600 символов в
  секунду, вопрос — доли секунды. Свежие CUDA-сборки torch не поддерживают
  старые карты (GTX 10xx, sm_61), поэтому `--device auto` проверяет GPU
  пробной операцией и при отказе остаётся на CPU.
- Сервер слушает только `127.0.0.1`. **`--host 0.0.0.0` открывает его всей
  сети без авторизации:** ключей и проверки доступа у сайдкара нет, любой в
  сети сможет кодировать тексты на вашей машине. Для доступа с другой машины
  — SSH-туннель или обратный прокси с авторизацией. Префиксы модели e5 (`query: ` /
  `passage: `) добавляет клиент, сервер кодирует текст как есть и отдаёт
  нормированные векторы.
- Другая модель: `--model BAAI/bge-m3` (1024 измерения, ~2,3 ГБ). Клиенту
  тогда нужно `EMBED_MODEL=BAAI/bge-m3`, а индекс — перестроить.

## Клиент приложения

Адрес и модель берутся из окружения (или `.env.local`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `EMBED_BASE_URL` | `http://127.0.0.1:8777` | адрес сервера эмбеддингов |
| `EMBED_MODEL` | `intfloat/multilingual-e5-base` | имя модели; по нему выбираются префиксы и проверяется индекс |
| `EMBED_API_KEY` | — | ключ (`Authorization: Bearer`), только для облачных API |

## Замена на Ollama или облако

Клиент говорит на OpenAI-совместимом `/v1/embeddings`, поэтому сайдкар
можно заменить без изменений в коде:

```sh
# Ollama (ollama pull bge-m3)
EMBED_BASE_URL=http://127.0.0.1:11434
EMBED_MODEL=bge-m3

# облачный API с OpenAI-совместимыми эмбеддингами
EMBED_BASE_URL=https://api.example.com/v1
EMBED_MODEL=<имя модели провайдера>
EMBED_API_KEY=<ключ>
```

У Ollama и облаков нет `/health` сайдкара — доступность проверяется по
`GET /v1/models`. Индекс, построенный одной моделью, другой не ищется:
после смены модели базу нужно переиндексировать.
