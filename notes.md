# Заметки по ходу — AnimalGuide v20: несколько MCP-серверов и длинный флоу

Черновик: план, решения по ходу, замеры. Заметки v19 — в истории git
(`git show v19:notes.md` в репозитории v19).

## Условие

Зарегистрировать несколько MCP-серверов. Агент выбирает нужный инструмент,
корректно маршрутизирует запросы, выполняет длинный флоу. Проверить сценарий
с инструментами разных серверов и корректность выбора и порядка вызовов.
Итог — длинный флоу взаимодействия с несколькими MCP-серверами.

## Что было в v19 и чего не хватало

Серверов по сути один бинарник в двух режимах: stdio (источники + MDD) и
HTTP-демон (то же + факты + конвейер), оба назывались `animals-sources`.
Клиенты — каждый к своему серверу: `mcp.Client` (только шесть инструментов
источников), `feed.Remote` (демон по HTTP). Реестра серверов, маршрута
«инструмент → сервер», агента с инструментами нескольких серверов и проверки
выбора и порядка вызовов не было.

## Архитектура: 3 + 1

Три архитектора независимо (минимум изменений / проверяемость / продукт и
наглядность), затем судья свёл их в одно решение:

- **Имена без префиксов.** Каждое имя закреплено за одним сервером явным
  списком `tools` в конфигурации; одно имя у двух серверов — ошибка
  конфигурации. Незаявленное (дубли источников у демона, платные
  инструменты) скрыто и видно в маршрутах с причиной. Префиксы
  `server__tool` отвергнуты: маршрут и так однозначен, а модели это лишний
  способ ошибиться.
- **Сервер опознаётся по имени в initialize** (`ServerOptions.Name`):
  `animals-sources`, `animals-daemon`, `animals-notes`.
- **Третий сервер — блокнот натуралиста** (`animals-mcp -role notes`):
  `nb_open` → `nb_add` × N → `nb_close`. Случайный `notebook_id` — зависимость
  данных, которую модель не угадает.
- **Агент — существующий `agent.Runner`** + завершающий `flow_done`, который
  код принимает, только если блокнот закрыт.
- **Проверка:** обязательные шаги, маршрут, зависимости данных (значение из
  ответа A в аргументах B), частичный порядок, запрещённые инструменты,
  покрытие серверов, ссылки `cites`, счётчики `server_info` до/после.
  Полный порядок не требуется. Мутационные тесты `Verify`.
- **Флоу «Паспорт вида в блокнот»** (манул): search_wikipedia →
  read_wikipedia → mdd_search → mdd_get → match_taxon → taxon_tree,
  vernacular_names → facts_get → nb_open → nb_add × 3 → nb_close → flow_done.

## План

- Этап 0: контракт — `ServerOptions.Name/Title/Instructions`, имя демона,
  `-role`, `feed.NewRemoteDial`, `pipeline.WriteVerified`, типы
  `hub`/`flow`/`hubapi`/`notes`, `web/hub.js`.
- Этапы 1–3 параллельно, три агента: серверы и реестр (notes, hub); движок
  флоу (flow, cmd/mcp-flow); REST и окно «MCP-серверы» (hubapi, hub.js, Edge).
- Этап 4: слияние, подключение в приложение, интеграционный тест с тремя
  настоящими серверами, живые прогоны.
- Этап 5: README, CHANGELOG, тег v20, контрольный прогон с видео.

## Ход работы

### 2026-09-25

- Задание заведено, основа — код v19 одним коммитом, модуль
  `AnimalGuide_Task20`, все тесты зелёные.
- Контракт (этап 0) написал сам; три агента параллельно в своих worktree от
  локального `main`: серверы и реестр (notes, hub), движок флоу и CLI (flow,

  альтернативы пути `a|b` во `Flow.Path`.
- Интеграция: `-mcp-config`, `app.Hub`, сквозной тест — встроенная
  конфигурация, три настоящих `mcp.Server` (демон по HTTP), реестр и флоу.
- Живые прогоны (демон на копии базы v19): все три сервера подключились,
  модели выдано 16 инструментов, 18 скрыто. Манул — 16 вызовов, всё ✓,
